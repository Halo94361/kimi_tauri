# tauri_kimi 方案

把 `kimi web`（Kimi Code CLI 的本地 Web UI）包装成一个双击即用的桌面应用：无浏览器地址栏，原生窗口，内嵌系统 WebView2。

## 总体架构

```
tauri_kimi.exe (Tauri 壳)
 ├─ 启动时：spawn 子进程 kimi web --no-open --port 58627
 ├─ 解析子进程 stdout 的就绪 banner，拿到实际端口和 bearer token
 ├─ WebView2 窗口 navigate 到 http://127.0.0.1:<port>/#token=<token>
 └─ 窗口关闭 / 子进程异常退出时：清理并退出（或显示断线页）
```

- 前端页面**不打包进 exe**：web UI 由 `kimi web` 同源服务，WebView 直接加载 localhost URL 即是完整页面。
- 壳自身只有两个本地静态页：`loading.html`（等待服务就绪）、`error.html`（服务断线/启动失败）。

## 技术选型

- **Tauri v2（Rust）**：Windows 上直接使用系统 WebView2，天然无地址栏；产物为单 exe，体积几 MB。
- **kimi 二进制**：调用系统已安装的 kimi（`~/.kimi-code/bin/kimi.exe`，已在 PATH），不内嵌。好处是 `kimi upgrade` 升级后壳自动跟随新版。
- 不经 PowerShell 中转，Rust 直接 spawn `kimi.exe`，避免引号转义问题、多余黑窗口和多层进程树。

## kimi web 关键行为（依据官方文档）

- 前台单进程，REST/WebSocket API 与 web UI 同源。
- `--no-open` 不自动开浏览器；`--port <port>` 指定端口，占用时自动 +1 重试（所以实际端口必须从输出解析）。
- 启动 banner 打印 bearer token；web UI 通过 URL 的 `#token=` 片段自动鉴权。
- 收到 SIGINT/SIGTERM 干净退出。

## 关键实现点

1. **加载等待**：先显示本地 loading 页；Rust 侧解析子进程 stdout，正则提取端口和 token，就绪后 navigate。
2. **外链拦截**：web UI 内的外部链接（文档、登录授权等）通过 `on_new_window` / 导航拦截，交给系统默认浏览器打开；仅放行 `127.0.0.1`。
3. **拖放文件**：`tauri.conf.json` 中必须设 `"dragDropEnabled": false`，否则 Tauri 会拦截系统拖放，web UI 的 HTML5 原生 drop 事件收不到，拖文件进会话会失效。
4. **生命周期**：窗口关闭 → kill 子进程 → 退出；子进程异常退出 → 切到断线页，可点击重启。
5. **剪贴板**：文本复制粘贴、截图粘贴均走 WebView2 原生能力，无需额外处理，验收时实测确认。
6. **快捷键/右键**：禁用浏览器语义的右键菜单；刷新类快捷键视需要处理。

## 验收清单

- [ ] 双击 exe → loading 页 → 自动进入完整 kimi web UI，无地址栏
- [ ] 输入框粘贴文本、粘贴截图正常
- [ ] 文件选择对话框上传正常
- [ ] 拖文件进会话正常
- [ ] UI 内外部链接用系统浏览器打开
- [ ] 关闭窗口后 kimi web 子进程被清理（无残留）
- [ ] 子进程被外部杀掉后显示断线页，可重启

## 风险与备注

- WebView2 Runtime：Win10(1809+)/Win11 基本预装；缺失时需引导安装 Evergreen Runtime。
- 端口占用重试意味着不能只假设 58627，必须解析实际端口。
- token 只出现在本地 URL fragment 中，不落日志。
